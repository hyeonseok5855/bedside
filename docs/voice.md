## 선택: NAVER CLOVA로 통일

STT와 TTS 모두 CLOVA. 비교 실험 없이 결정했다.

이득: 계정 하나, 인증 하나, 한국어 문서, 데이터가 국내 리전에 머문다.

## STT — CLOVA Speech (gRPC 스트리밍)

CLOVA 계열은 두 갈래다.

| 제품 | 성격 | 판단 |
|---|---|---|
| **CLOVA Speech** | NEST 엔진. 단문·장문·스트리밍 인식. gRPC로 실시간 인식 | **본 구현은 이쪽.** 5~10분 자유 대화에 맞다 |
| CSR (Speech Recognition) | 자체 스트리밍 프로토콜 모바일 SDK + REST | 짧은 발화 명령 위주라 본 구현에는 부적합. 다만 **첫 프로토타입 붙여보기엔 편하다** |

### 확인 필요

- [ ] **키워드 부스팅이 gRPC 스트리밍에서 지원되는가.**
      실제 병목은 평균 정확도가 아니라 사람 이름·지명이다. 프로필의 인물
      목록을 부스팅 사전으로 넘길 수 있으면 체감 정확도가 크게 오른다.
      스트리밍에서 안 되고 장문 배치에만 된다면 설계에 영향이 있다.
- [ ] **발화 종료 감지(EOT)가 스트리밍에 내장돼 있는가.**
      없으면 온디바이스 VAD(Silero VAD 등)를 직접 붙여야 한다.
      v1 공수에 며칠 추가된다고 잡아둔다.

### VAD

버튼을 눌러 말하는 방식은 쓸 수 없다. 5~10분 대화에서 열 번 버튼을 누르면
쓰지 않게 된다. EOT 내장이 아니면 VAD를 직접 구현한다.

저음량·속삭임 인식은 **필요 없다.** 방에 혼자 있을 때 쓴다.

## TTS — CLOVA Voice

- Volume, Speed, Pitch, Emotion 파라미터를 제공한다.
  밤 시나리오에 필요한 "느리게, 낮게, 차분하게"를 파라미터로 직접 통제할 수
  있고 재현성이 좋다. 톤 세팅을 한 번 잡아두면 매번 같게 나온다.
- **제약: 생성된 파일을 저장하거나 편집해 재사용할 수 없다.**
  따라서 "첫 질문 3개의 TTS를 미리 생성해 캐싱" 전략은 쓸 수 없다.

### 대안 — 미리 만들지 말고 빨리 시작한다

앱을 여는 순간 첫 문장 TTS를 즉시 호출하고, 그 사이 짧은 인트로 사운드나
화면 표시로 1초를 메운다. 첫 질문 텍스트는 밤 준비 단계에서 이미 만들어져
있으므로 왕복 한 번만 기다리면 된다.

## 폴백

**Android TextToSpeech를 v1에 반드시 넣는다.** 무료, 오프라인, 지연 0.
품질은 떨어지지만 네트워크가 끊겨도 대화가 죽지 않는다.

텍스트 입력 폴백도 v1에 포함한다.

## 지연 전략

지연이 UX의 전부다. STT → Claude → TTS 왕복이 매 턴 3초를 넘으면 대화가
아니라 취조가 된다.

1. **Claude 응답을 문장 단위로 잘라 TTS에 큐잉한다.** 전체 응답을 기다렸다
   합성하면 매 턴 2~3초가 그냥 날아간다. 첫 문장이 끝나는 즉시 재생 시작.
2. 첫 질문 텍스트는 밤 준비 단계에서 미리 생성해둔다. 앱을 여는 순간
   "잠깐만요, 오늘 데이터 분석 중..."이 뜨면 폰을 내려놓게 된다.
3. 질문은 한 번에 하나만. 음성이라 두 개를 붙이면 앞의 질문을 잊는다.

## 구조

**STT/TTS는 인터페이스 뒤에 둔다.** 벤더 SDK를 대화 로직에 직접 물리면
교체가 지옥이다. 교체 가능성은 높다.

## 비용

CLOVA Speech는 화자·이벤트 인식 없이 대략 분당 30원 안팎(10초 5원, 32초 15원
기준). 글로벌 대비 세 배쯤 비싸지만, 하루 10분 · 월 15일이면 월 4,500원
수준이라 결론은 바뀌지 않는다.

**일일 사용량 상한을 v1에 넣는다.** 정확한 요금은 공식 요금 페이지에서
확인할 것.

## 테스트 시 주의

성능 검증을 하게 된다면 **반드시 침대에 누워서** 한다. 누운 자세는 조음이
뭉개져서 앉아서 녹음한 것과 결과가 다르다. 사람 이름·회사명·동네 이름을
의도적으로 섞고, CER을 계산하기보다 "고유명사가 몇 개 살아남았나"를 센다.
