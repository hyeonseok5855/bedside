# Data Egress

기기 밖으로 나가는 데이터의 전수 목록. "로컬 우선"이 원칙이지만 STT·대화·TTS를
외부 API로 처리하는 이상 일부 데이터는 반드시 나간다. **불가피한 것을 숨기지
않고 여기에 전부 적는다.** 새 소스나 벤더가 늘면 이 표를 먼저 고친다.

작성일: 2026-07-27 · 관련 결정: 15(키/위협), 18(API 키), 21(이 문서)

## 나가는 것 (v1)

| 데이터 | 출처 | 목적지 | 무엇을 위해 | 형태 |
|---|---|---|---|---|
| 발화 오디오 | 마이크 | **CLOVA Speech** (국내) | STT | 원음성 스트림 |
| 인물 이름 목록 | 프로필 | **CLOVA Speech** (국내) | 키워드 부스팅 | 고유명사 사전 (지원 시, `voice.md` 확인 항목) |
| 발화 텍스트(transcript) | STT 결과 | **Anthropic** (해외) | 대화 | 텍스트 |
| 하루 브리핑 | 수집 DB 파생 | **Anthropic** (해외) | 질문 생성 | 텍스트 (아래 "브리핑에 담기는 것") |
| 프로필 | `나에 대하여.md` + `인물/*.md` | **Anthropic** (해외) | 시스템 프롬프트 | 텍스트, **인물 실명 포함** |
| 최근 일기 3~5편 | 일기 파일 | **Anthropic** (해외) | 문체 레퍼런스 | 텍스트 |
| AI 응답 텍스트 | Claude 출력 | **CLOVA Voice** (국내) | TTS | 텍스트 |

### 브리핑에 담기는 것 (Anthropic으로 나감)

- 위치: **좌표가 아니라 파생 체류/이동** ("집에 있음", "한강에서 45분"). 원시
  GPS 좌표는 기기를 떠나지 않는다.
- 사진: **메타데이터만** (촬영 시각·장소·장수). 이미지 자체는 v1에서 안 나간다.
- 건강: 몸무게·걸음·수면 수치.

## 나가지 않는 것 (기기에만)

- 원시 GPS 좌표, 원시 타임라인 DB
- 원본 사진 파일 (MediaStore URI만 참조, 복사 안 함)
- 생성된 일기 파일 (`Documents/Diary/*.md`)
- SQLCipher DB 및 그 키 (결정 15)

## 결정된 경계

- **인물은 실명(호칭)을 그대로 보낸다. v1에서 별칭 치환을 하지 않는다.**
  이유: 별칭으로 보내면 일기에 "A와 저녁"처럼 남아 1년 뒤 무의미하다. STT
  부스팅도 실명이라야 산다(`voice.md`). 프라이버시 이득보다 기록 가치의
  손실이 크다. 민감한 인물은 애초에 프로필에 넣지 않는 것으로 대응한다
  (`scope.md`의 "노출 토글은 v2" 판단과 같은 결).
- **사진 이미지 자체는 v1에서 나가지 않는다.** v2 vision을 켜는 순간 이미지가
  Anthropic으로 나간다 — 그때 이 표에 행을 추가하고 별도로 재확정한다. v1에서
  경계를 그어두는 이유가 이것이다(슬쩍 넘어가지 않게).
- **export 백업 키는 기기 키와 별개의 사용자 지정 키로 잠근다** (결정 15).
  백업 자체는 서버가 아니라 로컬 NAS/Syncthing으로만 흐른다(v2).

## 데이터 레지던시

- CLOVA(오디오·이름·응답 텍스트): **국내 리전** (`decisions.md` 6).
- Anthropic(transcript·브리핑·프로필·일기): **해외**. 대화 원문과 프로필이
  해외로 나간다는 것은 감수한 사실이다. 이 앱에서 이걸 피할 방법은 온디바이스
  LLM뿐인데 v1 범위가 아니다.
